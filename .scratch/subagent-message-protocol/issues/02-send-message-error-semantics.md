# send_message 的最佳努力与错误语义

## Answer

`send_message` 的新契约采用轻量最佳努力语义：

- 每个子代理内部保留一个串行 gate；多个调用在 gate 中依次执行，但不向模型暴露顺序或任何身份字段。
- 物理投递统一使用 adaptive Pi `prompt`，读取 raw response；匹配的 `success: true` 才返回最小的 `accepted` 成功结果。
- wire `success: false`、参数/状态拒绝和传输抛错都转成工具错误；这些错误不改变正常子代理的生命周期状态。只有进程 EOF 或不可恢复运行时故障才改变节点状态。
- 所有错误都允许模型依据系统提示词重试，包括传输结果不确定的情况；协议明确接受因此可能产生的重复或未定义投递，不引入 ACK、去重或任务身份来消除该成本。
- 成功只表示 Pi 方法调用返回接纳，不表示模型已读取、执行完成或父端已收到结果。

这张票的未决后果是需要单独决定重试次数、退避方式以及重复消息的容忍边界，见后续票「重试与重复消息的容忍边界」。
