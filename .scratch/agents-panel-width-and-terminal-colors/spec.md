# `/agents` 面板宽度与终态颜色优化规格

Status: ready-for-agent

## Problem Statement

用户在较宽的终端窗口中打开 `/agents` overlay 时，面板宽度最多只有 120 列，无法充分利用可用空间。较长的子代理名称、生命周期状态、activity、终止结果和摘要因此更容易被截断，宽终端中还会留下明显的空白区域。

面板当前也没有根据子代理生命周期状态建立视觉层级。`starting`、`idle`、`working`、`interrupting`、`terminating`、`terminated` 和 `failed` 行使用相同的普通文字颜色，用户难以快速区分仍可能继续推进的子代理与已经到达终态的子代理。

## Solution

将 `/agents` overlay 的最大宽度从 120 列提高到 160 列。面板继续由 Pi overlay 根据当前终端宽度和左右边距自动收缩，因此实际宽度为 160 列与当前可用宽度中的较小值；终端 resize 后重新计算布局，同时保留当前选择、展开状态和滚动位置。

沿用现有子代理生命周期定义，将 `terminated` 和 `failed` 视为终态。未选中的终态子代理行统一使用主题提供的弱化文字颜色，非终态行保持现有颜色。弱化样式覆盖该子代理行的全部可见文字；当终态行被选中时，现有高对比选中样式优先，移开选择后恢复弱化样式。常驻 agents widget 不在本次改动范围内。

## User Stories

1. 作为在宽终端中管理子代理的父代理用户，我希望 `/agents` 面板能展示更多横向内容，以便减少关键信息被截断的情况。
2. 作为在 160 列以上终端中工作的用户，我希望面板最大宽度达到 160 列，以便更充分地利用终端空间。
3. 作为在不足 162 列终端中工作的用户，我希望面板继续按可用宽度自动收缩，以便内容不会超出终端边界。
4. 作为在窄终端中工作的用户，我希望现有的截断和紧凑布局行为保持不变，以便本次优化不会破坏小窗口使用体验。
5. 作为会在运行期间调整终端大小的用户，我希望面板随 resize 自动重新计算宽度，以便无需关闭并重新打开 `/agents`。
6. 作为正在浏览代理树的用户，我希望 resize 不改变当前选中的子代理，以便继续查看同一运行节点。
7. 作为正在浏览长代理树的用户，我希望 resize 不重置滚动位置，以便不会丢失当前阅读位置。
8. 作为展开了部分代理树分支的用户，我希望 resize 不改变展开状态，以便布局变化不会改变正在查看的信息集合。
9. 作为管理多个并发子代理的父代理用户，我希望非终态子代理保持现有正常文字颜色，以便仍可能继续推进的节点维持当前可见度。
10. 作为扫描代理树的用户，我希望到达终态的子代理整行变暗，以便快速把注意力放在尚未终结的节点上。
11. 作为查看运行故障的用户，我希望 `failed` 行也被视为终态并变暗，以便终态视觉规则与生命周期语义一致。
12. 作为查看正常终止节点的用户，我希望 `terminated` 行变暗，以便已结束节点不会与活动节点争夺视觉注意力。
13. 作为比较不同终止结果的用户，我希望所有终态行使用相同的弱化颜色，以便颜色只表达“是否终态”，而不引入第二套结果分类。
14. 作为查看终态详情的用户，我希望树形连接符、名称、生命周期状态、activity、终止结果和摘要统一变暗，以便一行不会出现割裂的颜色层级。
15. 作为使用键盘导航的用户，我希望选中的终态行仍使用现有高对比选中样式，以便焦点位置始终清晰可见。
16. 作为从终态行移开选择的用户，我希望该行恢复弱化样式，以便终态和非终态的视觉层级重新显现。
17. 作为依赖明暗主题的用户，我希望颜色来自现有主题令牌，以便该功能适配宿主主题而不依赖硬编码 ANSI 或 RGB 值。
18. 作为色觉差异用户，我希望生命周期状态文字继续显示，以便不依赖颜色本身判断节点状态。
19. 作为使用常驻 agents widget 的用户，我希望 widget 的图标、文字和颜色保持不变，以便 overlay 优化不会改变常驻区域的视觉语义。
20. 作为依赖失败或终止通知的用户，我希望现有 host 通知级别保持不变，以便面板行颜色不会改变告警行为。
21. 作为使用 `/agents` 键盘操作的用户，我希望上下选择、左右展开折叠和关闭操作保持不变，以便无需重新学习交互方式。
22. 作为查看包含宽字符或不可信名称的用户，我希望现有显示列计算、文本净化、截断和补齐行为保持不变，以便面板仍能安全且整齐地渲染。
23. 作为遇到面板级错误的用户，我希望现有错误表面样式保持不变，以便生命周期行着色不会掩盖面板自身错误。
24. 作为项目维护者，我希望宽度和颜色行为由现有 overlay 测试接缝覆盖，以便后续重构可以发现用户可见回归。
25. 作为项目维护者，我希望测试同时覆盖终态、非终态和选中终态，以便样式优先级不会因条件顺序变化而退化。
26. 作为项目维护者，我希望完整检查继续通过，以便这项局部 UI 优化不会影响生命周期、树模型或插件构建。

## Implementation Decisions

- `/agents` overlay 使用数值宽度 160，并保留居中和左右各 1 列的现有 margin。Pi 根据终端宽度钳制实际宽度，因此实际结果为 `min(160, terminalColumns - 2)`，最低宽度继续由宿主现有规则处理。
- 不采用百分比宽度。Pi 原生支持百分比，但单个 overlay 不支持“百分比加最大宽度”；本次不通过双 overlay 或依赖求值顺序的副作用模拟该组合。
- 终端 resize 继续走宿主现有的重新渲染链路。宽度变化只影响布局，不重新创建面板模型，不重置选中节点、滚动偏移或展开集合。
- 沿用现有子代理生命周期状态闭集，不增加或修改状态。终态判定与现有生命周期语义一致，仅包含 `terminated` 和 `failed`。
- `starting`、`idle`、`working`、`interrupting` 和 `terminating` 继续使用当前普通正文前景色，不改变现有视觉表现。
- 未选中的 `terminated` 和 `failed` 行统一使用现有主题的弱化前景色。两种终态不使用不同颜色，`completed`、`failed`、`incomplete` 等终止结果也不影响行颜色。
- 终态弱化样式应用于整条用户可见代理信息行，包括缩进与树形连接符、名称、生命周期状态、activity、终止结果、摘要及折叠汇总文本。
- 样式优先级保持为：面板级错误表面按现有错误规则处理；选中行使用现有选中背景和高对比前景；其余终态行使用弱化前景；其余行使用普通正文前景。
- 选中的终态行不叠加弱化前景。选择移开后，重新渲染使该行恢复终态弱化样式。
- 状态文字和终止结果继续显示，颜色只作为辅助视觉层级，不成为唯一状态信息载体。
- 继续使用宿主主题接口及现有主题令牌，不新增颜色配置，不硬编码 ANSI 转义、调色板索引或 RGB 值。
- 保留现有显示宽度计算、Unicode 字素处理、安全文本净化、行截断、补齐、边框和 footer 行为。
- 改动范围仅限 `/agents` overlay 的宽度配置和代理行主题选择。常驻 agents widget、状态图标、spinner、host 通知、代理树数据、生命周期归约和管理命令行为均保持不变。
- 不新增公开 API、配置项、快照字段、协议字段或持久化数据，也不改变 Pi overlay 接口契约。

## Testing Decisions

- **测试原则**：测试用户可观察的 overlay 行为，不断言私有辅助函数、条件分支顺序或内部字段。样式测试通过 fake theme 输出可识别标记，验证最终可见行使用了哪一种语义主题，而不是绑定具体 ANSI 或颜色值。
- **主要测试 seam**：优先使用现有 `/agents` overlay UI 绑定作为最高层接缝。通过 fake host UI 打开面板，捕获 overlay 配置并渲染混合生命周期快照，从同一用户路径观察宽度配置、行内容和主题结果。
- **表面渲染接缝**：在需要精确控制选择和终端列宽时，沿用现有代理树面板表面渲染测试，不为本功能新增生产 seam。
- **宽度行为**：验证打开 `/agents` 时请求 160 列宽度，并保持现有居中与 margin；验证 160 列渲染结果的每行显示宽度稳定，窄宽度路径仍能安全截断且不溢出。
- **resize 行为**：对同一个面板模型以不同宽度连续渲染，验证布局宽度随之变化，同时选中节点、滚动偏移和展开集合不变。
- **终态颜色**：使用同时包含 `terminated`、`failed` 和至少一个非终态节点的树，验证两个终态的完整行均使用弱化主题，且不因终止结果不同而改变颜色。
- **非终态回归**：验证 `starting`、`idle`、`working`、`interrupting` 和 `terminating` 行继续使用普通正文主题。
- **选中态优先级**：选择一个终态节点后，验证整行使用现有选中背景和高对比前景，而不是弱化前景；移动选择后，验证原行恢复弱化主题。
- **整行范围**：测试数据应包含树形缩进、名称、状态、activity、终止结果和摘要，验证终态样式覆盖最终整行，而非只覆盖状态词。
- **面板错误回归**：保留并运行现有面板级错误样式测试，确认生命周期行着色不改变错误表面的优先级。
- **widget 回归**：保留并运行现有常驻 widget 测试，确认终态过滤、状态图标和未着色文本行为不变。
- **既有测试先例**：沿用代理树 UI 测试中已有的 fake UI、面板模型、主题注入、显示宽度断言和宽窄渲染用例；沿用生命周期测试对 `terminated` 与 `failed` 终态语义的定义。
- **完成门槛**：相关 UI 测试、类型检查、桥接构建和完整测试套件全部通过；不得通过更新无关快照或放宽断言掩盖回归。

## Out of Scope

- 将 overlay 改为无上限百分比宽度，或实现“百分比加最大宽度”的双 overlay 方案。
- 将最大宽度做成用户配置、命令参数或运行时可调设置。
- 修改常驻 agents widget 的颜色、图标、spinner、过滤规则或布局。
- 为 `failed`、`terminated` 或不同终止结果设计独立色相、成功色、警告色或错误色。
- 修改子代理生命周期状态闭集、状态转换、终止结果、activity 或快照协议。
- 修改代理树排序、折叠汇总、展开规则、选择规则、滚动算法或键盘绑定。
- 重设计 panel header、footer、边框、背景、错误表面或通知系统。
- 新增主题令牌、调色板设置或无障碍配置界面。
- 修改其他命令面板、消息 renderer 或常驻 UI 区域。

## Further Notes

- 当前 overlay 请求的最大宽度为 120 列，左右各有 1 列 margin；本规格将最大值提高到 160，保留相同边距和宿主钳制行为。
- 本规格使用项目领域语言：“子代理生命周期状态”描述运行节点事实；颜色变化不表示消息发送、Pi 接纳、最终报告或会话完成。
- `failed` 与 `terminated` 是生命周期终态，但 `terminated` 内部仍可能展示不同终止结果；这些结果继续以文字呈现，本规格不再用颜色细分。
- 测试接缝已根据现有 overlay UI 测试结构和本轮已确定的验收要求选定，无需新增生产接口。
- 本文件仅发布规格，不包含实现改动，也不在生成规格阶段运行构建或测试。
