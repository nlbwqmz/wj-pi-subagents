# 01 — 在加载期拒绝工具声明的修饰符形态

**What to build:** 模板作者在 `工具声明` 里写 `+name` / `-name`（无论单独出现，还是与普通工具名混用）时，模板被判为无效，并得到一条指向该模板与 `tools` 字段的诊断；纯工具名列表与含 `*` 通配的列表照常有效。作者因此不必等到子进程启动失败或静默少工具才发现写法不被支持。

**Blocked by:** None — can start immediately.

**Status:** resolved

- [x] 含 `+name`、`-name`、或修饰符与普通名混用的模板被判为无效，诊断定位到该模板与 `tools` 字段
- [x] 纯工具名列表、含 `*` 的列表（`*` 出现在首/中/尾、出现多次）仍判为有效
- [x] 既有 `tools` 相关诊断行为不变：非数组、空串、重复项、保留系统工具名
- [x] 诊断文案可读，说明修饰符形态不受支持（基准集来自宿主默认工具配置，扩展无法保证声明与实际一致）
- [x] 既有纯名字模板用例全部保持通过

## Answer

在模板发现加载期新增 `tool_modifier_unsupported` 诊断（与 `tools_invalid` / `reserved_tool` 同级）：`工具声明` 任一条目 trim 后以 `+` 或 `-` 开头（含与普通名混用）即判模板无效，诊断定位到该模板与 `tools` 字段；`*` 不新增形状限制（首/中/尾、多次出现均有效）。修饰符检查排在既有保留系统工具名检查之后，保证含保留名列表的既有 `reserved_tool` 行为不变。诊断文案说明修饰符形态不受支持，并给出理由：基准集来自宿主默认工具配置，扩展无法保证声明与实际一致。

- 实现：`src/template-discovery-snapshot.ts`（诊断码、加载期判定、诊断文案）
- 测试：`test/template-discovery-snapshot.test.ts` 新增 3 条用例（修饰符拒绝含 trim 与混用、`*` 任意位置/多次出现有效、保留名优先于修饰符含反序）
- 验证：`npm run typecheck` 通过；`npm test` 636 pass / 0 fail / 5 skipped（平台跳过）；单文件 18/18
