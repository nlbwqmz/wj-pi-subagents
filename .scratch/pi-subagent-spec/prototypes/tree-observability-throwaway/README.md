# 代理树可观测性原型（THROWAWAY）

> 这是用于验证 07 号票据展示决策的可抛弃原型，不是扩展生产代码，不应直接打包或发布。

## 要回答的问题

常驻 `Agents` widget 只显示当前会话的直接子代理，完整树通过 `/agent` 命令打开只读遮罩面板；当树较大时，面板是否仍能通过折叠、滚动和汇总保留关键状态？节点生命周期时间是否从 `spawn_agent` 成功返回开始计算？

## 运行

仓库没有现成任务运行器，直接使用已安装的 Node.js：

```powershell
node .scratch\pi-subagent-spec\prototypes\tree-observability-throwaway\demo.mjs
```

脚本构造一棵包含直接子代理、深层后代、工作中节点和失败节点的内存树，依次展示：

- 常驻 widget 只列当前会话的直接子代理；
- `/agent` 面板默认展开直接子代理、折叠后代；
- 展开分支后通过 viewport 滚动查看所有行；
- 被折叠分支保留后代数量和状态汇总；
- 时间从创建成功时刻计算，终止后的时长冻结；
- 失败状态和一次聚合通知不会被普通状态更新覆盖。

## 原型结论

- 直接子代理 widget 的高度与后代数量解耦，可以常驻在编辑器附近；
- 完整树适合放到独立遮罩面板，面板可以拥有自己的折叠和滚动状态；
- `template_id` 与展示名称并列比泛化的 `Agent` 标签更容易辨认角色；
- 折叠行必须保留后代数量、工作中数量、失败数量和 pending 数，不能静默截断；
- `created_at` 在创建成功时记录，节点失败或终止后只冻结时长，不回到零；
- 面板展示状态不需要把 prompt、工具参数、工具结果或 Token 统计放入 UI。

## 有意不做的内容

- 不启动真实 Pi RPC 进程，不调用 `ctx.ui.setWidget()` 或 `ctx.ui.custom()`；
- 不实现真实快捷键、终止按钮、消息发送或权限校验；
- 不模拟 token/费用统计、持久化、并发配额或生产级渲染性能。
