# 核实 Pi 文件访问与项目资源边界

Type: research
Status: resolved
Blocked by: 01

## Question

以 Pi 上游提交 `a96fb984d8c8b065fc5d193309fc812a882adee0` 的源码和官方仓库文档为一手来源，核实固定 RPC 子进程 `cwd` 后，内建读取、写入、编辑和 Bash 工具能否访问绝对路径或工作目录之外的路径；Pi 的项目信任判断以及扩展、技能、提示模板、上下文文件发现分别以什么路径为边界；独立扩展能否在不替换内建工具的前提下为不同子代理实施可靠的逐路径只读/读写授权。研究必须区分操作系统文件权限、工具可见性、路径级访问约束和项目资源自动发现，给出首版规格可以诚实承诺的边界。

## Answer

固定 RPC 子进程的 `cwd` 只决定项目身份、相对路径基点与资源自动发现，不构成文件访问边界。Pi 内建 `read`、`write`、`edit` 支持绝对路径和可越过 `cwd` 的 `..`；`bash` 也仅以 `cwd` 为初始目录，实际访问能力受宿主进程权限约束。因此，整棵代理树固定根 `cwd` 与按需访问工作目录外文件可以同时成立。

Project trust 只控制固定 `cwd` 对应的项目设置、扩展、技能、提示模板和系统提示等输入资源是否加载，不限制工具读写目标；访问外部数据路径也不会自动加载该路径附近的项目资源。`AGENTS.md`/`CLAUDE.md` 另按固定 `cwd` 的祖先链发现，不受 project trust 保护。

独立扩展可通过失败关闭的 `tool_call` 策略，为受控的结构化文件工具实施逐路径只读/读写检查，但这只是工具调用层策略。只要允许任意 `bash`、未知文件型工具或同权限扩展，就不能宣称存在不可绕过的文件系统边界；强隔离必须依赖 OS ACL、容器/VM、只读挂载或统一受控执行后端。

完整源码证据、资源发现矩阵与首版约束见 [Pi 文件访问与项目资源边界研究](../research/pi-filesystem-resource-boundaries.md)。
