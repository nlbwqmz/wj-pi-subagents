# 确定首版验收标准与规格交付结构

Type: grilling
Status: resolved
Blocked by: 02, 03, 04, 05, 06, 07, 08, 09, 11, 12

## Question

最终规格必须包含哪些可验证的行为场景、跨平台测试边界、失败与安全用例、性能或资源门槛及需求追踪关系，才能让实现代理无需补充产品决策即可实施，并让评审者判断首版是否满足临时分层代理树的全部约束？

## Answer

10 号票据将首版判定对象冻结为“开发阶段可实施交付”，不把 npm 发布、正式 tarball、release tag/commit 对应证明或发布报告混入本轮门槛。实现代理以 [Pi Subagent 独立扩展规格](../spec.md) 作为唯一规范入口；`map.md` 提供当前实现路线和工单导航，其他 issue、research 和 throwaway prototype 只提供决策依据与证据。

### 平台与宿主矩阵

- 当前开发里程碑只把 Windows 作为原生验收硬门槛；mock 不能替代 Windows Job Object 的真实进程树回收验收。macOS/Linux 代码可以先交付并接受类型、纯逻辑和 fake 测试，但原生 runner 与支持结论延期到独立计划。
- Windows 运行两个锁定组合：最低组合 Node `22.19.0` + Pi `0.84.1`；当前组合为验收开始时解析并立即锁定的最新稳定 Pi + 其支持的 Node Active LTS。证据必须记录精确版本；不做两端版本全排列。
- 低于最低版本、版本不可解析、必需 API 缺失和不支持平台通过集中式负向契约测试验证全有或全无兼容门禁；nightly、未发布 Pi commit 和 Node Current 不属于首版门槛。

### 五层自动化验收

1. 纯逻辑层使用 fake 和可控单调时钟覆盖状态机、配置解析与 UI-only 诊断、模板 schema/覆盖、能力与配额、树合并、UUID/字段校验、seq/ACK/重同步和脱敏。
2. Pi 契约层加载真实扩展入口和 `RpcClient`，验证七个管理工具 schema、错误外壳、事件映射、reload 和 UI-only 边界。
3. 原生进程集成层启动真实 `pi --mode rpc --no-session` 子进程，使用确定性本地假模型/提供者，验证创建、steering、中断、故障和整树回收。
4. TUI 层验证常驻直接子代理 widget、`/agent` 遮罩、滚动/展开/折叠/关闭、稳定尺寸和 UI-only 通知。
5. 本地 package 层在隔离临时目录验证 manifest 唯一入口、生产依赖、Pi 临时加载和本地持久安装 scope，并断言不隐式写入模板、配置或 Pi 设置。

Throwaway 原型只作为设计证据；关键断言必须迁入正式测试，人工探索不能替代自动化门槛。所有测试不得依赖外部模型网络、账号或 API key。

### Windows 双组合核心旅程

两个 Windows“宿主组合” job 都必须执行同一组核心旅程：加载扩展和模板；创建 A 并完成双握手后进入 `idle`；空闲任务、直接回复、`agent_settled` 等待和上下文延续；工作中 steering；A 创建深度 2 的 A-1 且叶节点隐藏管理工具；根整树只读且不能越级控制；状态 revision、pending 和父子关系一致；兄弟并行、单节点命令串行；协作式中断后复用；终止 A 时后代优先、资源确认、幂等和名额释放；成功 `/reload` 后新模板快照只影响后续创建，既有节点和 UI 状态保持不变。macOS/Linux 的同类旅程保留为后续独立计划，不在本里程碑以 skip 或 mock 记为通过。

### 负向、安全与资源矩阵

开发验收的功能矩阵必须逐项验证闭合公开错误码和无副作用，并覆盖参数与 UUID 格式、直接父所有权、模板发现/覆盖/信任、能力不足、深度/直接子代理/全树配额、配置文件故障回退和非法根参数拒绝、启动/RPC/消息/中断/终止竞态、父故障防孤儿、重复帧、断序、旧流、损坏快照、ACK 丢失与重同步。安全 canary 必须证明 project trust、模板开关和深度不能扩权，固定 `cwd` 不被误当作文件系统沙箱，并且秘密不出现在 UI、工具结果、错误、监督帧或模型上下文。Windows 必须真实验证终止、根退出和 reload 失败后无存活后代；macOS/Linux 对应原生断言延期且不能冒充已通过。

### 性能边界与证据

首版明确不做性能测试：不设置压力规模、吞吐量、延迟、绝对 RSS/句柄阈值、性能基线、benchmark 工件或 coverage 百分比门槛。已冻结的配额、协议有界保留、资源确认、名额释放和无孤儿断言只作为功能正确性与安全断言。

验收记录至少包含源码 commit、精确 OS/Node/Pi 版本、执行的 `AC-xxx`、逐项通过/失败结果、资源清理结论和脱敏日志/UI 快照；不得以 skip、quarantine 或自动重试掩盖失败，修复后重跑受影响场景。规格正文必须保持无 `TBD`、`TODO` 和产品未决项；未来发布运营事项另立任务。
