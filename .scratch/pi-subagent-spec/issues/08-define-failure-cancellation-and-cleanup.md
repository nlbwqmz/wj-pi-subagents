# 定义中断、失败与级联清理语义

Type: grilling
Status: resolved
Blocked by: 01, 03, 06

## Question

父会话中断当前处理、终止节点、子进程异常退出、启动失败、RPC 协议损坏、父代理退出和根会话退出时，直接子代理及其后代分别进入什么状态、向上报告什么结果并执行哪些清理？规则必须避免孤立进程，并明确超时、重复控制请求、部分级联失败及 Windows 进程树清理的行为。

## Answer

本票据冻结中断、故障、终止和资源清理的边界。它复用 03 号票据的七态生命周期、06 号票据的配额占用规则和 11 号票据的父子监督协议；12 号票据只负责把这里的时间边界和平台回收语义落成可测试的监督器接口。

### 1. 协作式中断不是终止

`interrupt_agent` 只请求当前处理停止并保留子代理节点及其上下文：

- 控制器接纳请求后立即将 `working` 变为 `interrupting`，工具返回 `accepted: true`，不等待 RPC `abort` 响应；
- 控制器向 Pi 任务通道发送 `abort`，但不清除已经被 Pi 接受的 steering；这些消息仍可能在中断后继续处理；
- `abort` 成功响应、`agent_end`、工具取消回调或局部 turn/message 结束都不能把节点变回 `idle`；只有 `agent_settled` 才能结束协作式中断并回到 `idle`；
- 中断期间可以接收新的父子消息，它们排在中断之后并继续计入 `pending_message_count`；
- 取消长期不响应时保持 `interrupting`，不自动升级为终止。父会话需要永久停止节点时，必须显式调用 `terminate_agent`；
- 如果中断命令在进程、RPC 或监督通道已无法可信使用时无法交付，节点进入 `failed`，不假设它已经停止。

因此，中断不会释放任何直接子代理或全树名额，也不会杀死子代理拥有的后代。它只改变当前处理的协作意图，终止仍是唯一的永久关闭路径。

### 2. 终止屏障与级联范围

`terminate_agent` 始终递归覆盖目标及其全部已登记后代，不接受只终止单个节点的开关。控制器在一个线性化点执行以下动作：

1. 校验目标是调用者的直接子代理，或是根关闭流程中的直接子树；
2. 固定目标及当时已登记的全部后代，建立不可逆的终止屏障；
3. 将所有尚未 `terminated` 的固定节点原子变为 `terminating`，取消尚未写入 Pi RPC 的普通命令；
4. 拒绝屏障后的新消息、创建和普通控制命令；已经被 Pi 接受的消息不追溯撤回；
5. 按后代优先、父节点最后的顺序执行资源清理和确认。

与终止屏障并发的子代理创建按同一顺序域裁决：在线性化点之前登记成功的节点纳入本次级联，之后才登记的请求被屏障拒绝，不能形成逃逸进程。旧 `agent_settled`、`agent_end`、队列事件、回复或监督帧均不能跨过屏障把节点恢复为 `idle`、`working` 或 `interrupting`。

### 3. 清理阶段和时间边界

每个终止流程使用独立的内部清理期限，不复用 `wait_agent.timeout_ms`，也不让调用者把它配置成无限等待。阶段顺序固定为：

1. **优雅阶段**：通过监督器要求子控制器及 Pi 会话停止接受新工作，发送关闭/EOF 或等价的 Pi 优雅关闭请求，并等待进程退出及后代确认；
2. **强制阶段**：优雅期限到达后，对仍存在的节点使用平台级进程树回收；
3. **确认阶段**：重新观察进程、IPC 端点和子树状态，只有全部资源都确认退出才能发布 `terminated`。

根会话退出、切换会话或扩展 runtime 关闭时，控制器自动对整棵代理树启动同一套级联终止，并在关闭流程中等待该内部清理期限。若期限结束仍无法确认部分资源退出，关闭流程报告 UI-only 错误并继续退出，不无限阻塞根会话。

### 4. 跨平台强制进程树回收

强制阶段必须以操作系统能够覆盖整棵进程树的原语为首选，不能只调用直接子进程的 `kill`：

- Windows：启动时把子进程加入该节点专用 Job Object；终止时优先关闭 Job Object 或使用其终止整个 Job 的能力，避免孙进程脱离；
- Unix 类系统：让节点运行在专用 process group 或 session 中，按优雅信号、进程组强制信号的顺序回收；
- 平台缺少上述能力时，按 PID 递归只能作为诊断或补救，不得声称已经安全回收整棵树；最终无法确认的节点必须保留 `termination_incomplete`。

端点、进程句柄、Job Object、process group 和原始异常只存在于监督器内部，不进入公开工具结果、树快照、widget、通知或模型上下文。具体 API 适配和测试替身由 12 号票据定义。

### 5. 故障分类与状态路径

#### 启动失败

节点在 `starting` 阶段发生进程启动失败、提前退出、RPC 握手失败、监督通道身份/版本不兼容、首个快照非法或启动期限到达时，先记录故障，再自动进入清理：

```text
starting -> failed -> terminating -> terminated
```

`spawn_agent` 只有在残余资源确认回收后才返回原始 `spawn_failed` 或 `spawn_timeout`。如果启动残骸无法确认回收，则节点停在带 `termination_incomplete` 的 `terminating`，调用返回顶层 `termination_incomplete`，安全详情保留原始启动错误和诊断 `agent_id`；该身份不可继续工作或复用。

#### 运行期故障

节点已经进入 `idle`、`working` 或 `interrupting` 后发生意外进程退出、RPC EOF、协议非法帧、身份/父子关系不匹配、序号无法重同步或快照校验失败时：

- 如果终止屏障尚未线性化，节点进入稳定 `failed`，携带 `internal_error` 或具体可归类故障码；
- 如果终止屏障已经线性化，退出属于终止流程，不再产生新的运行 `failed`；
- `get_agent_status`、`get_agent_tree` 和 `wait_agent` 仍可观察故障；`send_message` 拒绝，不能自动重启、降级或恢复；
- 监督器对该节点拥有的后代立即启动防孤儿清理。

已经发布的 `failed` 不会被迟到的 `agent_settled`、Pi `get_state`、旧回复或旧监督帧恢复。原始堆栈和端点信息只保留内部诊断；用户 UI 只显示稳定错误码和安全摘要。

### 6. 部分级联失败与幂等重试

清理流程按节点独立推进，一个失控后代不能阻塞同一子树中其他节点的优雅或强制回收：

- 已确认资源退出的节点立即进入 `terminated`，成为当前根会话的终止记录，不再占直接子代理或全树名额；
- 仍有资源未确认的节点保持 `terminating`，携带 `termination_incomplete` 并继续占用名额；
- 父节点只有在所有后代和自身资源都确认 `terminated` 后才能进入 `terminated`；
- `terminate_agent` 等待整个目标子树到达内部清理边界。只要仍有未确认节点就返回 `termination_incomplete`，`details` 只列安全的未确认节点标识和阶段；
- 同一目标的并发或重复终止请求合并到同一清理流程。已完成部分不重复执行，后续幂等调用只继续确认未完成节点；
- 不自动重试、排队或重启。调用方可以在资源状态改变后再次显式调用同一终止工具。

### 7. 中间父代理和根会话退出

中间父代理进程异常退出时，直接父控制器先将它记为 `failed`，然后对其已经登记的全部后代建立防孤儿终止屏障。该父代理不自动重启、不复用 `agent_id`，也不能继续接收消息或恢复为工作状态；后代清理完成前它仍占用名额。只有直接父会话显式终止该故障节点，并确认其子树全部回收后，才进入 `terminated` 并释放名额。

根会话退出、`new`、`resume`、`fork` 或扩展 runtime 关闭不需要用户逐个终止：根控制器对所有直接子代理启动同一套原子级联清理。根关闭完成后释放终止记录，不跨会话恢复或保留进程。

### 8. 错误、通知和验收场景

本票据不新增公开错误码。沿用 `spawn_failed`、`spawn_timeout`、`termination_incomplete`、`internal_error`、`agent_unavailable` 以及 02 号票据的其他闭合集合；清理阶段、平台句柄和原始异常通过安全 `details` 表达，不把底层阶段名扩展成公开错误码。

实现必须至少覆盖以下可重复场景：

- 中断接纳后 `abort` 返回但迟迟没有 `agent_settled`，节点持续 `interrupting`，随后显式终止成功；
- 已接受 steering 在中断后继续执行，消息计数和最终 settle 不越过终止屏障；
- 启动超时、握手身份错误和首个快照损坏均形成 `starting -> failed -> terminating`，并正确释放或保留名额；
- Windows Job Object、Unix process group/session 均能回收孙进程；平台回收不完整时保留 `termination_incomplete`；
- 父节点崩溃后后代全部进入防孤儿清理，故障父节点直到显式终止前保持 `failed`；
- 一个后代强制回收失败时，兄弟节点仍完成终止，父节点继续 `terminating`；重复终止只推进未完成部分；
- 终止屏障与子代理创建/退出并发时，先线性化的一方决定是否纳入，迟到事件不能恢复节点；
- 根退出在内部期限内完成时不遗留进程，超期时只产生 UI-only `termination_incomplete`，不阻塞退出且不提前释放未确认名额。

结论是：中断保留节点，终止永久关闭；所有级联清理先建立终止屏障、再优雅关闭、最后使用操作系统级进程树回收，并以资源确认而不是信号发送成功作为 `terminated` 的条件。部分失败可观察、可重试且不会制造孤儿或虚假的已回收状态。
