# 确定代理模板发现与信任策略

Type: grilling
Status: resolved
Blocked by: 01, 14

## Question

用户级与项目级代理模板应如何发现、校验、去重和覆盖，项目模板何时需要人工确认，模板允许声明哪些字段，以及模板在父子递归创建中如何引用而不突破 Pi 的项目资源信任边界？

## Answer

本票据定义 Pi Subagent 扩展的根控制器如何发现、校验、发布和刷新代理模板。模板是 UTF-8 Markdown 文件，frontmatter 定义角色配置，正文定义可为空的角色提示。模板目录、project trust、有效模板目录和诊断都由根会话拥有；后代只消费根会话当前发布的模板发现快照，不能自行扩大来源或改变信任边界。

### 来源、身份与信任

- 用户级来源固定为 `~/.pi/agent/agents/*.md`，项目级来源固定为根 `cwd` 下的 `<cwd>/.pi/agents/*.md`。两者都只扫描目录直属文件，不递归子目录。
- 只接受目录直属、以 `.md` 结尾的普通文件或符号链接。符号链接以其目录项文件名派生身份；目标不可读或失效时是无效候选模板。
- 模板标识 `template_id` 是原始文件名去掉末尾 `.md` 的结果。匹配精确区分大小写，不裁剪、不转小写、不做 Unicode 归一化、别名或模糊匹配，也不增加文件名字符限制；同名文件能否共存由宿主文件系统决定。
- 项目模板只有根会话已经信任项目资源时才是候选来源。该根 project trust 结果固定地传给整棵树；模板不能提升、降低或重新确认它。未获信任的项目目录不参与发现，使用同名用户模板时不需要额外确认。
- 根 project trust 是项目模板唯一的人工确认边界。项目获信任后，根及所有后代创建项目模板不做逐模板或逐次确认。
- 缺失的用户级或已获信任项目级目录是正常空来源。目录存在但无法枚举时，记录来源级模板发现诊断并继续使用另一来源的成功结果；该诊断没有 `template_id`，不新增错误码。

### 模板格式与已知字段

每个候选文件都按 UTF-8 读取，并要求可解析的 YAML frontmatter。frontmatter 缺失、无法解析、已知字段类型错误、枚举值错误、未知业务工具名、文件不可读或符号链接失效都使该候选模板无效。Markdown 正文允许为空。

已知字段如下；未列出的 frontmatter 字段一律静默忽略，不进入运行配置，也不产生诊断。因此 `name` 不是模板字段，不能影响 `template_id` 或覆盖关系。

| 字段 | 规则 | 创建时语义 |
| --- | --- | --- |
| `tools` | 必填，只接受 YAML 字符串，不接受数组、空值或其他类型。`tools: ""` 是唯一合法空工具集。非空字符串以逗号拆分、裁剪、丢弃空项并按首次出现顺序去重；若最终没有工具名则无效。 | 规范化后的完整业务工具集必须在创建瞬间被直接父会话当前有效工具集完整覆盖；缺少任一项返回 `template_capability_unavailable`，不得静默削减。 |
| `description` | 可选字符串；裁剪后为空视为无描述。 | 仅是父代理可见的展示元数据，不参与模板身份、能力判断或子代理提示。 |
| `subagents` | 可选枚举 `inherit` 或 `disabled`，默认 `inherit`。 | 遵循 04 号票据的树控制面规则；`disabled` 关闭当前节点及后代全部七个管理工具。 |
| `contextFiles` | 可选枚举 `enabled` 或 `disabled`，默认 `enabled`。 | 只控制固定 `cwd` 祖先链上的 `AGENTS.md` / `CLAUDE.md` 发现；各节点独立选择。 |
| `systemPromptMode` | 可选枚举 `append` 或 `replace`，默认 `append`。 | 采用模板正文追加或替换子代理的项目与角色提示层；安全、所有权、通信、工具契约和已启用上下文文件仍保留。 |
| `model` | 可选，按 04 号票据的精确 provider/model 选择规则校验。 | 省略时捕获直接父会话已解析的精确模型；格式错误为 `template_invalid`，静态不可用为 `template_capability_unavailable`。 |
| `thinking` | 可选，按 04 号票据的固定枚举和模型支持范围校验。 | 省略时捕获直接父会话实际等级；格式错误为 `template_invalid`，静态不支持为 `template_capability_unavailable`。 |

模板不提供 `name`、`env`、`skills`、`extensions`、`promptTemplates` 或项目资源信任控制字段。它们即使出现在 frontmatter 中也作为未知字段静默忽略；对应运行时继承与加载规则由 04 号票据固定。

### 校验、覆盖与创建解析

根会话会独立读取和校验所有已获信任来源中的候选文件，即使一个候选文件会被同名高优先级来源遮蔽。校验结果分为有效候选项、无效候选项和来源级诊断。

- 同一 `template_id` 同时存在项目级和用户级候选项时，项目级候选项整体覆盖用户级候选项，不合并字段或正文。
- 覆盖决定创建时使用的候选来源。若项目级候选项无效，它仍遮蔽同名合法用户候选项，不回退到用户模板；该标识不可创建。
- 若项目级候选项合法、用户级同名候选项无效，项目模板照常可创建；被遮蔽的用户文件仍在根会话诊断中列出，但不改变该标识的创建结果。
- `spawn_agent.template_id` 先按上述来源规则精确解析候选项，再判断该被选中候选项是否有效。没有被选中候选项时返回 `template_not_found`；被选中候选项无效时返回 `template_invalid`；有效候选项再进入 04 号票据规定的模型、思考等级、业务工具、深度和名额预检。
- `template_invalid` 的安全详情可以说明来源、文件名和简短原因，不能包含模板正文、底层绝对路径、环境、操作系统异常或堆栈。被合法高优先级候选项遮蔽的低优先级无效项只留在诊断信息中，不会让创建返回 `template_invalid`。
- 目录扫描失败是来源级诊断而不是某个无效模板；从当前快照中查不到的标识仍是 `template_not_found`。只有无法归类的控制器内部故障才使用 `internal_error`。

### 发现快照、重载与诊断

根会话在首次启动以及根会话执行 Pi `/reload` 后进行一次发现。扩展不做文件监听、持续校验或运行期能力复核。

- 每次发现完成后，根控制器原子发布一个新的模板发现快照，其中包含有效模板目录、无效候选模板诊断和来源级诊断。整棵树此后所有 `spawn_agent` 调用使用同一个当前快照。
- `/reload` 的新快照只影响后续创建。既有子代理的模板正文、模型、工具、提示、生命周期和状态不回溯修改。
- 根重载遇到某一来源目录无法扫描时，仍发布由本轮成功来源组成的部分新快照，并以本轮诊断替换旧诊断；旧快照中仅来自失败来源的模板不会作为过期回退保留。
- 子代理自身的 `/reload` 不重新发现模板、不改写根控制器快照，也不产生根级模板诊断提示。

只要当前发现轮存在无效候选模板或来源级诊断，根会话就通过一次 `ctx.ui.notify(message, "warning")` 输出汇总警告。每项只显示逻辑来源（`user` 或 `project`）、文件名或来源目录、以及安全的短原因；不输出正文、绝对路径、环境、秘密或异常堆栈。没有诊断时不显示通知。

该通知是 UI-only 的瞬时信号：TUI 直接显示，RPC 以独立的 `extension_ui_request` / `notify` 交给客户端；它不会创建 user/assistant 消息、会话条目、系统提示或模型上下文，且不得使用 `sendMessage`、`sendUserMessage` 或其他消息注入 API 替代。print/JSON 等无 UI 模式仍会建立同一发现快照和诊断，但 `notify` 为 no-op，不另设 stderr、结构化事件、持久化条目或模型消息回退。

### 模板示例

```markdown
---
description: 汇总并核对外部资料
tools: read, grep, find
subagents: inherit
contextFiles: enabled
systemPromptMode: append
---

优先给出可核对的来源和结论。
```

该文件若名为 `researcher.md`，则其唯一公开标识为 `researcher`。无业务工具的模板必须写成 `tools: ""`；正文可以在第二个 `---` 后留空。

### 验收要点

1. 用户与获信任项目来源均存在时，只扫描直属 Markdown 文件；未获信任项目来源完全不参与发现。
2. 任一候选文件的读入、链接、frontmatter 或已知字段错误不会阻断其他有效模板，且仅在根会话 UI 汇总中出现。
3. 无效项目模板覆盖同名有效用户模板时，该标识返回 `template_invalid`；合法项目模板覆盖同名无效用户模板时，该标识仍可成功创建。
4. `tools: ""` 合法，`tools: " , "` 无效，`tools: "read, , grep, read"` 规范化为 `read, grep`。
5. 模板诊断通知不会进入会话历史、系统提示或模型上下文；无 UI 模式不产生替代输出。
6. 根 `/reload` 后只有后续创建使用新快照，既有节点保持不变；失败来源的旧模板不保留为回退。
