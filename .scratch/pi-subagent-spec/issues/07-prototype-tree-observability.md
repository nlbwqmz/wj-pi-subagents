# 设计代理树视图与流式交互

Type: prototype
Status: resolved
Blocked by: 02, 03, 06, 11

## Question

根会话的只读代理树视图、普通父会话的直接子代理视图，以及创建、执行、引导、中断、失败和级联终止时的流式反馈应展示哪些信息、采用何种折叠与展开交互，并如何在不授予越级控制权的前提下让用户和模型准确判断整棵树的状态？

## Answer

本票据冻结 Pi Subagent 的只读代理树可观测性。原型位于 [代理树可观测性原型](../prototypes/tree-observability-throwaway/README.md)，它验证常驻直接子代理 widget、`/agent` 遮罩树、折叠/滚动、生命周期计时、终止汇总和 UI-only 故障通知；它不启动真实 Pi RPC 进程，也不作为生产渲染代码。

### 1. 两个用户入口与可见范围

#### 常驻 `Agents` widget

常驻 widget 是默认的用户可见入口，但只显示**当前会话的直接子代理**，不渲染后代树：

- 根会话显示根的直接子代理；
- 普通父会话显示自己的直接子代理；
- 不显示祖先、兄弟或越级后代；
- widget 只读，不提供发送、中断、终止、重载或其他控制按钮；
- 行首使用模板文件名得到的 `template_id`，不使用泛化的 `Agent` 标签。

该范围让常驻区域高度与整棵树规模解耦。普通父会话即使只拥有自己的局部作用域，也使用同一行格式和同一套字段。

#### `/agent` 遮罩面板

用户输入 `/agent` 时，扩展打开一个 TUI 临时遮罩面板查看完整树；它是独立的本地 UI 命令，不把命令文本或面板内容提交给模型：

- 根会话的作用域为整棵代理树；
- 普通父会话的作用域为自身及其后代子树，作用域根是该父会话；
- 面板只读，不扩大父会话的通信、创建或终止权限；
- 打开时读取当前一致的 `tree_revision`，随后实时跟随控制器发布的新修订；
- 默认展开当前作用域的直接子代理，后代分支折叠；
- 支持上下滚动、左右展开/折叠，`Esc` 关闭；面板关闭不改变树；
- `finished` 区域默认折叠，包含已进入 `terminated` 的终止记录和汇总计数；终止记录不再占活动树名额。

widget 和面板都只消费 11 号票据规定的控制器确认快照，不读取模型正文、Pi 原始日志或未经顺序校验的事件。RPC 宿主可以消费 `setWidget` 和自定义 UI 请求并自行渲染；print/JSON 模式没有可见 UI，不为本规格增加文本输出回退。

### 2. 常驻行字段

活动直接子代理每行最多显示以下信息，字段顺序稳定，长文本必须截断到行宽：

```text
├─ refactor  Refactor auth module  working · editing 2 files · 12.3s
├─ explore   Find auth files       idle · 16.0s
└─ long-task Long-running task     failed · rpc_unavailable
```

- `template_id`：模板文件名去掉末尾 `.md` 的精确值，区分大小写；
- 展示名称：`spawn_agent` 的 `name`，只用于阅读，不能寻址；
- 生命周期状态：`starting`、`idle`、`working`、`interrupting`、`failed`、`terminating`；`terminated` 不留在活动行而进入 `finished`；
- 安全活动摘要：仅由控制器在已确认的工具边界映射出的短类别和计数，例如 `editing 2 files`；不得使用原始 prompt、assistant 正文、工具参数、工具结果或路径；
- 创建成功后的生命周期总时长：从 `spawn_agent` 完成 RPC 与监督通道握手、节点进入 `idle` 并成功返回的瞬间开始；
- 非零 `pending_message_count`：为零时省略，避免无信息噪声；
- 当前故障码：仅在 `failed` 或带 `termination_incomplete` 的 `terminating` 中显示稳定错误码。

不显示完整 prompt、assistant 正文、工具参数/结果、文件路径、环境变量、进程句柄、异常堆栈、Token/费用百分比或模型内部推理。展示名称和活动摘要均按行宽截断，截断不得导致相邻行重排或覆盖。

### 3. 时间与状态反馈

控制器在子代理创建成功的线性化点记录 `created_at`，并使用单调时钟计算 elapsed；RFC 3339 的 `observed_at` 只用于诊断和快照新鲜度，不能用于计算时长或排序。

- `starting` 尚未成功创建，不显示正常生命周期时长；
- `idle`、`working`、`interrupting` 和 `terminating` 显示从创建成功开始的累计时长；
- `failed` 或 `terminated` 时冻结最终时长，不回到零；
- 该时长表示子代理生命周期，而不是当前 prompt 或工具调用耗时。

widget 和面板按照控制器确认的事件更新，不按逐 token 流刷新：

| 控制器事实 | UI 变化 |
| --- | --- |
| 消息被控制器接受 | 增加 `pending` 计数；不提前显示 `working`。 |
| Pi RPC 确认空闲节点开始处理 | 显示 `working`，并清除对应 pending。 |
| 工具边界确认 | 更新截断的安全活动摘要；不显示参数、结果或路径。 |
| 中断请求被接纳 | 显示 `interrupting`；不因 `abort` 响应或 `agent_end` 提前恢复。 |
| 级联终止屏障被接纳 | 目标子树显示 `terminating`；终止记录仍留在树快照中。 |
| 全部资源回收确认 | 从活动行移入 `finished` 汇总，冻结时长并释放名额。 |
| 运行故障被确认 | 显示 `failed` 和稳定错误码；不被迟到正常事件覆盖。 |

一次控制器提交可能同时改变多个节点（例如级联终止）；UI 按一个新的 `tree_revision` 原子刷新，不能显示半棵已终止、半棵未终止的中间树。正常状态变化只刷新 widget/面板，不发送通知。

### 4. 完整树的折叠与大树行为

常驻 widget 不承担后代树高度问题；完整树的空间管理全部由 `/agent` 面板负责：

- 面板有独立 viewport，内容超出高度时滚动，不静默截断；
- 直接子代理默认展开，后代默认折叠，用户可逐分支展开或折叠；
- 折叠分支必须显示后代总数、工作中数量、失败数量和 pending 总数；
- `failed`、`terminating`、`interrupting`、`working` 和 `starting` 分支优先保持可见；纯 `idle` 分支可以折叠，但仍保留完整汇总；
- 已终止节点不混入活动树行，统一放入默认折叠的 `finished` 区域，并显示完成数量、失败终止数量和仍未完成清理数量；
- 任何节点都不能因为空间不足而无提示地消失。若渲染器发生内部异常，面板显示 UI 错误状态，不伪造完整树。

树的内容来自一个单一 `tree_revision` 的完整快照。面板保持自己的展开集合和滚动位置；新修订只替换节点数据，不强制用户回到顶部或丢失已经展开的分支。作用域变化（例如普通父会话本身被终止）关闭该面板并由控制器处理资源清理。

### 5. 故障通知与上下文边界

正常状态变化只更新 UI。节点进入 `failed` 或出现 `termination_incomplete` 时，根控制器对当前可见作用域内同一批状态变化聚合发送一次 `ctx.ui.notify`：运行故障使用 `warning`，无法完成终止清理使用 `error`；通知正文只含模板标识、数量和稳定错误码，不含路径、prompt、参数、结果或堆栈。

通知、widget 更新、`/agent` 面板内容、`tree_revision` 和协议诊断均为 UI-only/控制器数据，不追加到 Pi 会话消息、不进入系统提示、不进入模型上下文。RPC 宿主是否实际显示通知由宿主决定；无 UI 模式保持无可见输出，但不改变控制器状态。

结论是：常驻 `Agents` widget 负责低高度、可持续扫描的直接子代理状态；`/agent` 负责按权限查看完整树、折叠和滚动。两者共享安全快照、稳定生命周期状态和创建生命周期计时，不授予越级控制权，也不把可观测性数据泄露给模型上下文。
