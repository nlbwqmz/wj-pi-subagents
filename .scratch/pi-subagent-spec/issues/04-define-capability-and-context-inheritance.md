# 确定子代理能力与上下文继承规则

Type: grilling
Status: resolved
Blocked by: 01, 02, 13, 14, 15

## Question

创建子代理时，工作目录、模型、思考等级、系统提示、工具、扩展、技能、提示模板、上下文文件、环境变量及项目信任状态分别如何选择、继承、收窄和隔离？规则必须保证后代不能扩大祖先授予的权限，并能在达到 `maxDepth` 时彻底移除子代理管理工具。

## Answer

本票据将子代理的配置分成两类：由扩展持续强制的树控制面，以及只在创建时用于准入和初始化、之后交由 Pi 动态管理的业务运行时。逐级能力衰减对前者始终成立；模板业务工具集对后者只构成创建时条件，不是进程级沙箱或不可变资源快照。

### 固定基础与文件访问

- 整棵代理树固定使用根会话的同一 `cwd`。模板、父会话和后代都不能覆盖它；相对路径和项目资源发现均以该目录为基点。
- `cwd` 不是文件系统边界。只要模型可见的工具和宿主权限允许，子代理可以使用绝对路径或 `..` 访问工作目录之外的文件；首版不提供逐路径授权。
- 根会话的 project trust 结果由整棵树原样继承，模板不能提升或关闭。它只影响项目设置和资源加载，不限制普通文件访问。
- 模板不提供 `env` 字段。控制器在建立代理树时捕获根环境快照，后代均从该快照启动；只能追加不可覆盖的节点身份、父标识、深度、`maxDepth` 和协议版本等内部元数据。秘密不得进入状态、树视图、错误或日志。

### 创建时能力预检

创建前只做扩展能够稳定回答、且直接影响创建契约的检查：

1. 解析模板 Markdown 与 YAML frontmatter，校验必填字段、字段类型、枚举和已知工具名。模板正文允许为空。结构错误使用 `template_invalid`。
2. 每个模板必须显式声明业务 `tools`；规范化后的空集合表示没有业务工具，省略字段不是继承父工具。控制器以创建瞬间父会话当前有效业务工具集为准，要求它完整包含模板声明。缺少任一项时返回不可重试的 `template_capability_unavailable`，且不预留名额、不登记节点、不启动子进程；不能静默删减模板工具。模板文件中的具体序列化形式由 05 号模板规格确定。
3. `model` 省略时捕获直接父会话当时已经解析出的精确 provider/model；显式值按当前模型目录和根策略做静态精确匹配。`thinking` 省略时捕获父会话当时的实际等级；显式值校验固定枚举及当前已知模型支持范围。格式错误使用 `template_invalid`，静态已知不可用使用 `template_capability_unavailable`。
4. 深度、直接子代理名额和 `subagents` 管理能力按控制器规则检查。只有通过上述预检后，才允许原子预留名额、登记 `starting` 节点并启动 RPC 子进程。

预检不探测模型 API、认证是否能完成一次真实请求，也不计算环境、提示、技能、扩展、上下文文件、资源清单或工具注册表的哈希。创建成功前只需完成一次无副作用的 RPC 请求与响应，证明子进程和协议可通信；这不是最终配置或能力证明。失败和超时分别沿用 `spawn_failed` 与 `spawn_timeout`。

### 模板配置与上下文

- `subagents` 取 `inherit` 或 `disabled`，省略默认 `inherit`。`disabled` 会对当前节点及全部后代永久关闭七个子代理管理工具；`inherit` 也不能突破祖先关闭状态或 `maxDepth`。
- `contextFiles` 取 `enabled` 或 `disabled`，省略默认 `enabled`。它只控制固定 `cwd` 祖先链上的 `AGENTS.md` / `CLAUDE.md`，每个模板独立选择；父节点关闭不阻止子模板启用。
- `systemPromptMode` 取 `append` 或 `replace`，省略默认 `append`。模板正文可以为空；`replace` 只替换项目与角色提示层，不能删除扩展注入的所有权、直接父子通信、工具和树控制契约，且已启用的上下文文件仍保留。
- 子代理不继承父会话渲染后的系统提示或对话历史。技能、扩展和斜杠提示模板不提供模板级白名单，按固定 `cwd`、统一 project trust、统一用户资源目录和 Pi 的正常发现规则加载。

### 运行时 reload

Pi 的 `/reload` 以及扩展运行时 API 可以重新加载扩展、技能、提示模板和上下文文件，也可以动态注册或调整活动业务工具。创建成功后，控制器不再比较模板 `tools` 与子代理实际活动工具，不校验资源或配置哈希，也不会因为 reload 改变业务资源而降级、终止或重新创建节点。模型、思考等级和业务资源后续发生的 Pi 原生动态变化同样不触发模板能力复核。

模板 `tools` 因此只表达创建准入和初始工具请求。运行期间如果资源或活动工具变化，按 Pi 正常行为处理；若变化导致一次任务失败，该失败走 Pi 与既有节点生命周期，而不是回溯成 `template_capability_unavailable`。

树控制面是唯一例外。扩展每次初始化或 reload 后都必须依据控制器保存的节点身份重新施加直接父子所有权、`subagents` 的祖先关闭状态和 `maxDepth`，据此完整暴露或隐藏七个管理工具；服务端仍重复校验深度和直接父子权限。reload 不能恢复祖先已经移除的子代理管理能力，但也不需要完整能力握手。
