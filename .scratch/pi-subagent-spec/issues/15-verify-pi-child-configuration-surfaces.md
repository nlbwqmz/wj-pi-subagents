# 核实 Pi 子进程模型、提示与资源装配入口

Type: research
Status: resolved
Blocked by: 01, 13, 14

## Question

以 Pi 上游提交 `a96fb984d8c8b065fc5d193309fc812a882adee0` 的源码和官方仓库文档为一手来源，核实独立扩展创建无会话 RPC 子进程时，模型、provider、思考等级、系统提示、工具、扩展、技能、提示模板、上下文文件、环境变量和 project trust 分别可通过哪些公开 CLI、SDK 或 `RpcClient` 入口确定；各入口的默认继承、发现、覆盖、禁用和失败行为是什么。研究应重点判断：哪些值能在启动前严格验证，哪些由子进程启动后才解析；如何用 `--no-*` 与显式路径得到确定资源集；宿主环境变量默认如何传入；哪些行为是 Pi 正式契约、源码事实或必须由本扩展补足的严格能力检查。

## Answer

`RpcClient` 只是标准 CLI RPC 子进程包装器：它可传 `cwd`、宿主环境覆盖、provider/model 与任意 CLI 参数，但默认复制完整 `process.env`，只等待约 100 ms 判断进程是否提前退出，没有 ready 或能力握手。`--no-session` 仅使用内存会话，不关闭设置、认证、资源发现、缓存或环境读取。

Pi CLI 与公开 SDK 能装配模型、思考等级、系统/追加提示、工具、扩展、技能、提示模板、上下文文件和 project trust；`--no-*` 通常关闭自动发现但保留显式资源路径。不过多项默认行为不是失败关闭：未知工具被静默忽略，非法 thinking 可能只警告或被 clamp，provider 存在但模型 ID 未命中时可能构造 custom model 继续启动，技能和提示模板错误也不一定阻止 RPC 启动。这些事实说明，若产品要求冻结并证明最终资源快照，就必须增加扩展自有能力握手；本规格随后在 04 号票据中明确不采用该重型保证，只保留模板结构、创建时必需工具和显式模型/思考字段的静态校验，启动后允许 Pi 正常动态 reload。

固定根 `cwd`、project trust、资源自动发现、工具可见性、环境变量和 OS 权限是独立维度。标准 `RpcClient.env` 只能在继承完整宿主环境后覆盖，不能形成环境白名单；若规格要求删除敏感变量、精确系统提示或排除固定 Pi 内建扩展，需要自定义 spawn 或薄 SDK/RPC 入口。

完整入口矩阵、失败语义、预检顺序与确定性启动建议见 [Pi 子进程模型、提示与资源装配面研究](../research/pi-child-configuration-surfaces.md)。
