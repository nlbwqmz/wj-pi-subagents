# 04 — 嵌套调用适配

**What to build:** codemode 脚本内的嵌套调用不再伪装成独立直接调用——产生端采集 Pi 事件上的 `parentToolCallId`；面板把嵌套调用显示为独立条目并在工具名前加 `codemode->` 前缀（多级链完整拼接为 `codemode->A->B`，超过 3 层时中间省略为 `codemode->…->B`）；嵌套条目自身的摘要与折叠能力保持（该有摘要的照常显示、该可折叠的照常可折叠）；单次调用超过 256 条嵌套记录时在面板上聚合显示"其余 N 条省略"。

**Blocked by:** 03 — tool_search 与 MCP 适配

**Status:** resolved

- [x] 面板对嵌套条目渲染 `codemode->` 前缀；多级链按完整调用链拼接，超 3 层中间省略
- [x] 嵌套条目自身的摘要渲染不回归（如嵌套的 `read` 显示 path、嵌套的 MCP 工具显示 server/tool）
- [x] 嵌套条目的折叠/展开能力与普通条目一致（不因前缀改变交互）

- [x] 活动事实语义不变：嵌套条目与普通条目同等待遇（活动窗口裁剪、滚动、选中），不改变生命周期

## Answer

实现只覆盖工单 04 的嵌套调用采集、显示与聚合，未改动 02/03 的来源判定、专用摘要与截断规则。

- **产生端**（`src/rpc-bridge-event.ts`）：工具开始/结束事实新增可选 `parentToolCallId`；`normalizeOwnToolActivityEvent` 在两条事实上原样采集（无父引用时条目形状不变），非法父引用由 wire 校验拒绝。
- **wire 闭集**：`parseAgentActivityEvent` 与 `parseCanonicalAgentActivityEvent` 接受可选父引用；新增 `isValidParentToolCallId`——父引用必须是有界非空文本、不得自引用，且 `toolCallId` 必须形如 `<父 id>/<n>`（Pi 嵌套调用 ID 规则）；未知键、越界、自引用与不一致组合一律拒绝。嵌套条目仍按原来源分派专用摘要。
- **面板**（`src/agent-activity-viewer.ts`）：工具条目新增 `nestedPrefix` 显示前缀，由父链投影得出——`codemode->A->B` 完整拼接，超过 3 段中间省略为 `codemode->…->B`；前缀只加在工具名前（摘要宽度相应扣除），不参与摘要内容、展开体、选中与折叠交互。父条目未被观察到时以 `codemode` 根标记兜底；开始事实缺父引用而结束事实携带时，结束事实补齐前缀。
- **超量聚合**：`NESTED_ACTIVITY_DISPLAY_LIMIT = 256`；单次顶层调用的嵌套记录逐条显示至 256 条，超出部分在首个超量记录位置聚合为一行 `其余 N 条省略`，后续超量记录只累加计数（`nested_omitted` 投影条目，不参与选中/展开）。计数与聚合按运行实例隔离，不同运行实例复用同一根活动 ID 不串联。
- **决策说明**：① 超量聚合是查看器投影层保证（spec Testing Decisions S4 指定的接缝）：父端活动窗口为 100 atom，运行中的工具不被裁剪，因此并发运行的嵌套调用超过 256 条时快照可达并触发聚合；窗口本身按工单「活动窗口裁剪同等待遇」与 spec Out of Scope 保持不变。② 父条目缺失时的 `codemode` 兜底是 spec「已知边界」内的降级呈现（当前只有 codemode 能执行嵌套调用）。③ 前缀根名取自观察到的调用链，未来编排型扩展工具同样适用，不需要契约变更。
- **验证**：`npm run check`（`tsc --noEmit` + 全量测试）通过：633 pass / 0 fail / 5 skipped（共 638 项）。新增 11 个用例覆盖：产生端父引用采集与非法父引用拒绝、wire 闭集（未知键/自引用/不一致/越界）、`codemode->` 前缀与多级链省略、嵌套摘要与折叠/选中/生命周期不变、256 超量聚合（含增量累加、运行实例隔离与结束事实补齐前缀）、原始 Pi 事件 → 产生端 → 面板端到端、活动缓存 → 面板端到端。
- **代码审查**：Standards 轴无硬性代码违规（工单写回属流程项，已在本提交完成）；采纳的判断题：超量计数与聚合按运行实例隔离、结束事实补齐嵌套前缀。未采纳：领域术语表未新增（`CONTEXT.md` 已有「活动条目/活动事实」等上位术语，嵌套为特性词）、测试工具位置参数改 options（沿用文件既有风格）、聚合文案提为常量（模板含变量，与静态文案常量不同类）。Spec 轴确认验收项 1–7 均满足；对「聚合在真实链路可达性」的疑问已用 `AgentActivityCache → AgentActivityViewerModel` 端到端用例补证（运行中的嵌套调用不被 100 atom 窗口裁剪），并记录窗口不变属工单既定约束。
