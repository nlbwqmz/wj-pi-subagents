# v0.7.0

## 破坏性变更

- 最低 Pi 版本提升至 **1.2.0**。扩展在旧版 Pi 上以软禁用方式加载：只提示当前版本与要求版本，不注册任何工具。使用 `^0.6.0` 的用户不会自动升级到 0.7.0，升级到本版本即表示接受新的宿主基线。

## 新增

- 10 个工具全部声明 `outputSchema`，成功结果附带 `structuredContent`（与既有 `details` 一致）：codemode 脚本与自动化调用方可以直接消费对象，无需解析 JSON 文本。
- 工具失败改为 `isError` 返回，不再抛出异常；错误对象保留 `{ ok: false, error }` 结构与全部稳定错误码。模型可见的错误文本与之前完全相同。
- 10 个工具新增语义标注：查询类工具标 `readOnlyHint`，`terminate_agent` 标 `destructiveHint`，`spawn_agent` 标 `openWorldHint`，权限类扩展可以据此自动放行或请求确认。
- 10 个工具统一归入 `subagent` namespace：codemode 的 `describeNamespace` 可以一次取到全部工具文档，`tool_search` 按 namespace 分组展示。namespace 不改变工具名，模型看到的仍是原名。
- 工具结果行尾新增 dim 耗时段（例如 ` · 4.2s`），成功与失败结果都会显示；格式与 Pi 内置工具一致：`4.2s` / `3m 15s` / `1h 5m 30s`。
- `wait_agent` 与 `get_agent_status` 的结果新增 `aborted` 字段：可以区分“被取消”与“正常完成”。

## 迁移

1. 将 Pi 升级到 1.2.0 或更高版本。
2. 更新扩展：`pi update --extension npm:wj-pi-subagents`。
3. 无需改动模板：工具名没有变化，既有的提示词、模板与脚本继续有效。
4. 错误处理可以按需调整：如果此前依赖捕获异常或解析错误文本，现在可以直接读取工具结果的 `isError` 与 `structuredContent`；不调整也能继续工作。
